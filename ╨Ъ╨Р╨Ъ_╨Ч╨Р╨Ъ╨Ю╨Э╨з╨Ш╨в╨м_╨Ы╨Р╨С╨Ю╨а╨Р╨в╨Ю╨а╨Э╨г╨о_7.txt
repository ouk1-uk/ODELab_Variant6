ЛАБОРАТОРНАЯ №7, ВАРИАНТ 6 — ЧТО СДЕЛАТЬ ДЛЯ СДАЧИ
====================================================

ВАЖНО: по методичке нужен фрагмент кода в отчёте, но НЕ полный листинг.
Обязателен настоящий скриншот запуска Google Test и ссылка на GitHub.
Также лабораторная №7 должна опираться на библиотеку лабораторной №4.

1. ОТКРОЙ ПРОЕКТ
   Распакуй ZIP. Корень проекта — папка ODELab_Variant6 с CMakeLists.txt.
   Установи Visual Studio (именно Visual Studio, не VS Code) с компонентом
   «Разработка классических приложений на C++» (Desktop development with C++),
   CMake и Ninja.
   Открой Visual Studio -> File -> Open -> Folder -> ODELab_Variant6.

2. НАСТРОЙ GOOGLE TEST ЧЕРЕЗ VCPKG
   Если vcpkg уже установлен, настрой VCPKG_ROOT на его папку.
   Если нет, в Developer PowerShell for Visual Studio выполни:

     git clone https://github.com/microsoft/vcpkg.git "$HOME\vcpkg"
     & "$HOME\vcpkg\bootstrap-vcpkg.bat"
     $env:VCPKG_ROOT = "$HOME\vcpkg"
     [Environment]::SetEnvironmentVariable('VCPKG_ROOT',$env:VCPKG_ROOT,'User')

   Закрой и заново открой Visual Studio, чтобы переменная была доступна.
   В Developer PowerShell перейди в папку ODELab_Variant6 (cd ПУТЬ_К_ПАПКЕ),
   затем выполни:

     & "$env:VCPKG_ROOT\vcpkg.exe" x-update-baseline --add-initial-baseline
     cmake --preset windows-debug
     cmake --build out/build/windows-debug

   Первая команда добавит в vcpkg.json настоящий builtin-baseline.
   Это изменённый vcpkg.json обязательно включи в GitHub.

   Если команда cmake пишет, что не найден компилятор cl.exe, используй
   Developer PowerShell for Visual Studio, а не обычный PowerShell.
   Если не найден GTest, проверь путь VCPKG_ROOT и ошибки конфигурации CMake.

3. ПРОВЕРЬ ТЕСТЫ И СДЕЛАЙ СКРИНШОТЫ
   В той же папке выполни:

     .\out\build\windows-debug\ODETests.exe
     ctest --test-dir out/build/windows-debug --output-on-failure
     .\out\build\windows-debug\ODEDemo.exe
     .\out\build\windows-debug\AntipatternDemo.exe

   Успешный запуск ODETests обычно заканчивается строкой:
   [  PASSED  ] 29 tests.
   Цифра 29 относится к текущему коду; если при запуске будет иная —
   сохраняй настоящий результат и разбирайся с расхождением.

   Сделай скриншот действительного вывода ODETests.exe, где видны
   результаты и финальная строка. Win + Shift + S -> выделить окно ->
   сохранить PNG (например, google_test_pass.png).
   Дополнительно полезно сделать скриншот ODEDemo.exe с выводом
   "Previous trajectory preserved: true" и строками [enter]/[exit].
   Скриншоты не создавай искусственно: снимай именно свои запуски.

4. ОТРИЦАТЕЛЬНЫЙ САМОКОНТРОЛЬ (В ТРЕБОВАНИЯХ ОБЯЗАТЕЛЕН)
   Исходная реализация уже проходила локальную проверку с намеренной ошибкой,
   журналы в verification/*.txt. Для полноценного подтверждения настоящим
   Google Test можно воспроизвести эксперимент в Visual Studio:

   - Скопируй src/ODETask.cpp в резервную копию ВНЕ папки проекта.
   - В методе void ODETask::solve(...) прямо перед строкой
       std::vector<ODEPoint> prepared;
     временно добавь:
       trajectory_.clear();  // НАМЕРЕННАЯ ОШИБКА
   - Выполни сборку и тесты ещё раз:
       cmake --build out/build/windows-debug
       .\out\build\windows-debug\ODETests.exe
   - Убедись, что тесты сильной гарантии сообщают об ошибке, сделай
     скриншот отрицательного теста (полезно приложить к отчёту).
   - ОБЯЗАТЕЛЬНО удали добавленную строку, собери заново,
     запусти все тесты и убедись, что они снова проходят.
   - Не загружай испорченную реализацию на GitHub.

5. ДОПОЛНИ WORD-ОТЧЁТ
   Открой файл Звіт_ЛР7_Варіант6_Оновлений.docx.
   - Впиши ФИО, группу и, при необходимости, преподавателя.
   - В разделе 7 в ячейку с рамкой вставь настоящий скриншот Google Test.
     В Word нажми в ячейке Ctrl+A (осторожно: выдели только текст ячейки),
     удали текст-заглушку и вставь изображение через Вставка -> Рисунки.
   - По реальному выводу уточни числа прошедших тестов и формулировку
     в отчёте, не выдавай локальную проверку за запуск Google Test.
   - При желании добавь скриншот ODEDemo и проваленного теста после
     соответствующих разделов (методичка явно требует скриншот Google Test).
   - После публикации вставь ссылку на GitHub в раздел 10.

6. GITHUB
   Создай репозиторий на GitHub, например "ode-lab-7-variant-6".
   Для проверки преподавателем проще Public; Private требует дать доступ.
   Из корня проекта в Developer PowerShell или терминале Git:

     git init
     git add .
     git commit -m "Lab 7 variant 6 - ODE exceptions and tests"
     git branch -M main
     git remote add origin URL_СВОЕГО_НОВОГО_РЕПОЗИТОРИЯ
     git push -u origin main

   Перед этим не создавай в новом репозитории GitHub README/LICENCE, иначе
   может понадобиться разрешать конфликт первых коммитов.
   В .gitignore уже исключены /out, /build и бинарные файлы.
   Убедись, что на GitHub видны include/, src/, tests/, demo/, antipattern/,
   README.md, CMakeLists.txt, CMakePresets.json, vcpkg.json.

7. СДАЧА
   Передай преподавателю готовый Word-отчёт и ссылку на GitHub (и ZIP,
   если LMS требует архив). Полный листинг кода в Word не нужен.
   Проверь, что вариант №6 совпадает с вариантом лабораторной №4.
   Если у тебя есть исходники лабораторной №4, сравни и адаптируй проект:
   методичка требует модернизацию именно прежней библиотеки.

Обрати внимание: отчёт пока содержит место для скриншота и пустую ссылку.
Без этих материалов называть его окончательно готовым нельзя.
